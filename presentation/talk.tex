% ---------------------------------------------------------------- 1. problem
\begin{frame}{The same sum, twice, different answers}
\begin{columns}[T]
\begin{column}{0.52\textwidth}
\small
Reduce the \emph{identical} bytes on a cluster.\\[2pt]
Reshape it. Reduce again.
\begin{itemize}\small
  \item Floating-point addition is not associative.
  \item Changing the worker count changes \emph{which operands pair}.
  \item So the bit pattern changes.
\end{itemize}
\vspace{4pt}
We measured it rather than asserting it: across \GpuWorldSizes{} world sizes,
\GpuRootsDistinct{} distinct roots on identical input.
\end{column}
\begin{column}{0.46\textwidth}
\figvar[1.0]{f01_premise/a}
\end{column}
\end{columns}
\end{frame}

\begin{frame}{Why this matters}
\begin{itemize}
  \item Debugging: a run that cannot be reproduced cannot be bisected.
  \item Regulation and audit: ``same input, same output'' is often a requirement.
  \item Elasticity: cloud clusters reshape \emph{by design}.
\end{itemize}
\vspace{6pt}
\begin{block}{The usual answers}
Fix the worker count (gives up elasticity), or sort/compensate at every step
(costly, and still order-dependent under reshape).
\end{block}
\end{frame}

% ---------------------------------------------------------------- 2. theory
\begin{frame}{The idea: name one order, and make it a contract}
\begin{columns}[T]
\begin{column}{0.46\textwidth}\small
Fix a \emph{canonical} reduction tree $\FBT(N)$ --- heap-indexed, leaves in
ascending index order.

\vspace{4pt}
The result is defined by the \emph{tree}, not by the machine that walks it.

\vspace{4pt}
The compiler must prove it emits that tree; the fabric must refuse to execute
anything else.
\end{column}
\begin{column}{0.52\textwidth}
\figvar[1.0]{f02_canonical_tree/a}
\end{column}
\end{columns}
\end{frame}

\begin{frame}{Property 2 --- fail-stop, not wrong-answer}
\begin{columns}[T]
\begin{column}{0.48\textwidth}\small

\begin{frame}{Cross-topology invariance holds}
\begin{itemize}
  \item Every passing configuration yields a single root per instance.
  \item Mutation testing: the oracle is not vacuous --- reordering
        \emph{does} change the root, at \OrderLRDiff{} of the sixteen leaf counts.
\end{itemize}

% ---------------------------------------------------------------- 6. honesty
\begin{frame}{What we got wrong}
\begin{columns}[T]
\begin{column}{0.50\textwidth}\small
Our own FP64 adder had a defect on effective subtraction --- and our Python
oracle was a transcription of that RTL, so it agreed.

\vspace{4pt}
Found by scoring against references \emph{external} to the design: exact
rationals and the host FPU.

\vspace{4pt}
\FpAcceptErrors{} errors on \FpAcceptVectors{} vectors after repair, beside a
control that fires on \FpCtrlErrors{} of \FpCtrlVectors{}.
\end{column}
\begin{column}{0.48\textwidth}
\figvar[1.0]{f12_fp64_defect/a}
\end{column}

\begin{frame}{Limitations we are not hiding}
\begin{itemize}
  \item No silicon: RTL simulation of a single-chip fabric.
  \item No measured same-fabric $\eta$ at non-power-of-two scale. At
        power-of-two, $\eta = 1$ is a \emph{theorem}, not a measurement.
  \item The suite confounds $N$ and $G$; no cell-level recommendation is derivable.
  \item The software export is slower than stock NCCL, and we say by how much.
\end{itemize}
\end{frame}

\begin{frame}{Takeaway}
\begin{block}{}
Reproducibility across reshape is achievable as an \emph{interface contract}:
the compiler proves the order, the fabric refuses anything else, and the
result stops depending on the shape of the machine.
\end{block}
\vspace{6pt}
\begin{itemize}
  \item Bitwise-identical roots across six topologies.
  \item Fail-stop rather than silently wrong.
  \item A four-configuration portfolio that transfers to unseen topologies.
\end{itemize}
\end{frame}
