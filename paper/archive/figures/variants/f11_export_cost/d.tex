% f11_export_cost variant d -- the paired chunking arms, and the sign flip.
% Data: experiments/w_final/W2/v004/COST.json, cost_table rows backend=nccl,
%   G=2, dtype=fp64, N=8, arms fbt_ch1 and fbt_ch2, field overhead.  Both arms
%   share the same stock_us at each size, so the printed ratio is exactly
%   fbt_us(two chunks) / fbt_us(one chunk).  Scalars: data/wround_macros.tex.
% Mechanism, from the released driver (tree_allreduce in
%   experiments/w_final/W2/*/libfreeze/w_worker.py): with C chunks the vector
%   is cut into C pieces and the piece index selects which side of each
%   internal node roots it, so at C=2, G=2 each rank roots one half.  That
%   halves the bytes on the critical path and doubles the number of dependent
%   send/broadcast pairs.
% Strategy: this is the only variant that isolates the EFFECT of a change
%   rather than the level of the overhead, and it is the evidence that
%   separates the two cost terms.  The same algorithmic change costs 1.81x to
%   2.78x below 1 MiB and pays back 0.94x to 0.84x at 32-128 MiB.  A cost that
%   reverses sign with message size is dominated by per-call launches at the
%   small end, not by the tree.  Variant a shows the same two series as levels
%   and cannot make this argument.
% Scope: NCCL only; gloo excluded as a broken baseline (\PinGlooBadRatio{}x
%   inversion in message size at G=\PinGlooBadWorld).
